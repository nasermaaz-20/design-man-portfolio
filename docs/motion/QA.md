# فحص الحركة وشروط القبول

الحالة: سجل فحص دفعة التنفيذ بتاريخ 2026-11-08. نجح build، وفحص الأنماط الآلي دون ملاحظات، و9 اختبارات bootstrap، وحالات المتصفح الموضحة أدناه. المربعات المفتوحة حالات إضافية لم تُتحقق بشكل مستقل، ولا تمثل نتائج ناجحة.

## نتيجة الدفعة

- 9 اختبارات Node للمهلة، التجاوز، تقليل الحركة، الجلسة، منع التخزين، وwatchdog عند فشل التطبيق: ناجحة.
- 13 حالة متصفح فريدة في Chromium: 6 للديسكتوب و7 لمحاكاة Pixel 7. حالة قائمة الهاتف تُتجاوز عمداً في مشروع desktop.
- في جولة المتصفح الأولى ظهر خلل تركيز بعد التجاوز، وخلل مراقبة الصورة المقصوصة بالكامل. صُلّحا وتم تأكيدهما. حالة السكرول على الهاتف احتاجت تصحيح الفحص ليضع العنصر نفسه داخل الشاشة بدلاً من توسيط قسم أطول من الشاشة؛ لم يتطلب ذلك تغييراً إضافياً بالواجهة.
- مراجعة صور Hero ومعرض الأعمال وProcess على الهاتف والديسكتوب: مكتملة. الصور في مجلد test-results المحلي المتجاهل في Git.
- تحقق HTTP للمعاينة وموارد HTML المبنية: ناجح. لا مسارات أصول مكسورة في HTML الناتج.
- المعاينة المحلية: `http://127.0.0.1:4173/`. الأوامر: `npm run build` و`npm run test:bootstrap` و`npm run test:e2e`.
- لم تُقَس Core Web Vitals أو FPS على جهاز فعلي، ولم تُختبر Safari/iOS أو Firefox أو HMR. لا يوجد وعد بنتيجة Lighthouse أو أداء ميداني. لم تتوفر صور baseline قبل التنفيذ؛ المقارنة الرقمية تخص حجم البناء فقط.

## بيئات الفحص

| الحالة | المقاس/الطريقة |
| --- | --- |
| هاتف ضيق | `360×800`، لمس |
| هاتف | `390×844`، لمس |

| ديسكتوب | `1440×900`، مؤشر دقيق وكيبورد |

محاكاة الهاتف تفحص التكوين والوظيفة؛ لا تثبت سلاسة GPU على هاتف حقيقي.

## التفاعلات

- [ ] hover لا ينازع حركة الدخول؛ اللمس لا يحتاج hover لفتح مشروع.
- [x] قائمة الهاتف تعلن حالتها وتغلق بـEscape مع عودة التركيز للزر.
- [x] الحوار له اسم، ويحبس focus، ويغلق بالكيبورد، ثم يعيد التركيز للكرت.
- [ ] فتح/إغلاق/إعادة فتح سريع، وفتح مشروع مختلف أثناء الخروج، لا يتركان callbacks قديمة.
- [ ] حوار طويل يمرر محتواه، والخلفية ثابتة حتى نهاية الخروج ثم تعود لنفس الموضع.
- [ ] مصدر الصورة خارج الشاشة أو تغيّر المقاس يفعّل fallback نظيفاً للانتقال المشترك.
- [ ] المؤشر الأصلي متاح على الأجهزة اللمسية الكبيرة وعند عدم تهيئة المؤشر المخصص.

## تقليل الحركة والأداء

- [ ] تقليل الحركة يلغي العمق والستارة والعدادات المتحركة، مع بقاء المعلومات والـfocus ظاهرة.
- [x] تغيير تفضيل تقليل الحركة أثناء الجلسة يبقي العناصر قابلة للقراءة دون بقاء opacity صفر.
- [ ] RAF واحد لـLenis، وتنظيف المراقبين والحركات والمستمعين عند unmount.
- [ ] لا loops زخرفية مستمرة في الإصدار الأساسي، ولا blur/shadow متحرك على مساحة الشاشة.
- [ ] فحص DevTools لا يظهر layout متكرراً بسبب حركة المؤشر أو السكرول. هدف الضبط قرب 60fps على الجهاز المختبر، وليس ضماناً لكل الأجهزة.
- [ ] سجل حجم JS المضغوط قبل/بعد، وأسباب أي زيادة؛ لا نفترض أن حذف مكتبة يكفي لإثبات التحسن.
- [ ] سجل LCP وCLS وTBT في المختبر قبل/بعد بنفس الإعدادات، وافحص الاستجابة بالتفاعل. INP يحتاج عينات تفاعل/بيانات ميدانية مناسبة ولا يُستنتج من TBT وحده.
- [ ] لا نؤخر المحتوى عمداً لإكمال العرض الافتتاحي. تُراجع مهلة وشكل المقدمة إذا أضرا بالتحميل.

## التحقق العملي والتسليم

بعد تغييرات التنفيذ: شغّل `npm run build` ثم `npm run preview`، وافحص النسخة المبنية لا dev فقط. أُضيف test:bootstrap لاختبارات الافتتاحية وtest:e2e لمتصفح Chromium على الهاتف والديسكتوب. لا تسجل حالات المتصفح كناجحة قبل تشغيلها.

جولة بصرية واحدة مجمعة للهاتف والديسكتوب، إصلاح واحد مجمع، ثم جولة تأكيد عند الحاجة. لا تكرر تحسينات مفتوحة بلا عيب محدد. فحوص lifecycle والوظائف أعلاه مستقلة عن التنقيح البصري.
